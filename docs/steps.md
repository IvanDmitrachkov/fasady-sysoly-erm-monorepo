# ERM «Фасады Сысолы» — Этапы разработки v1.0

---

# 🧭 Общая стратегия разработки

Документацию по проекту **не сопровождаем формальным semver** (номера в шапках файлов — ориентир, без процедуры релизов доков).

Порядок работ может отличаться от этапов ниже, если так удобнее разработке; стек и UI зафиксированы в [technology-stack-and-ui.md](./technology-stack-and-ui.md).

Система строится по принципу:

> сначала поток производства → потом экономика → потом операции → потом аналитика → потом удобство

---

# 🟢 ЭТАП 0 — База (Foundation)

## 🎯 Цель
Поднять технический каркас системы.

## Backend
- Node.js + TypeScript + Fastify
- подключение MySQL (Beget)
- Prisma ORM + миграции
- базовая структура модулей
- авторизация (**JWT**) и **роли с первого дня**: администратор, работник (цех), заказчик — модель прав на API; **без подролей**, один цех (все работники эквивалентны)

## Frontend
- React + Vite + TypeScript
- базовый layout
- роутинг (React Router)
- API client слой
- разделение сценариев по роли (в т.ч. **кабинет заказчика**: заказы организации, read-only)

## CI/CD
- GitHub Actions
    - build frontend
    - deploy на Beget (FTP)

## 📦 Результат
- система запускается end-to-end
- пустой UI + API работает
- вход и ограничения по ролям заданы сразу (без откладывания RBAC на поздние этапы)

# 🟡 ЭТАП 1 — Ядро системы (Orders + Stages)

## 🎯 Цель
Сформировать производственный поток.

## Backend
- CRUD заказов
- CRUD этапов (динамические), у этапа флаг **«это готово»** (финальный) по BR §4.2
- перемещение заказа между этапами
- **audit log по BR** (п. 11): пользователь, время, тип, **короткий текст** (MVP без усложнения); на этом этапе — смена этапа и изменения полей заказа; фасады и цена — в этапе 2

## Frontend
- список заказов
- создание заказа
- карточка заказа (минимальная)
- канбан доска этапов
- админка этапов: порядок, создание/редактирование, флаг **«это готово»**
- заказчик: список и просмотр заказов **своей организации**
- просмотр audit log — **только администратор** (см. BR §11.1)

## 📦 Результат
- заказ движется по цеху вручную

# 🟠 ЭТАП 2 — Фасады и стоимость

## 🎯 Цель
Добавить экономическую модель.

## Backend
- фасады внутри заказа
- в заказе поля **overridePercent**, **overridePrice** (nullable) + итоговая стоимость; **базовая цена считается на фронте** по данным заказа
- расширение audit log: изменения фасадов и цены (короткий текст, MVP)

## Frontend
- форма фасадов
- поля заказа **overridePercent**, **overridePrice**
- расчёт базовой цены по правилам из BR
- отображение стоимости заказа

## 📦 Результат
- система считает деньги

# 🟣 ЭТАП 4 — Раскрой (stateless модуль)

## 🎯 Цель
Производственная функция раскроя.

## Backend
- cutting service (stateless)
- группировка фасадов:
    - material (MDF)
    - thickness
- генерация раскроя по группам
- **без сохранения** результата раскроя и PDF на диске: расчёт + **генерация PDF библиотекой на сервере** и отдача **потоком** в HTTP-ответе
- доступ к эндпоинтам раскроя/PDF: **администратор и работник (цех)**

## Frontend
- кнопка “Раскрой”
- результат в новой вкладке
- PDF: запрос к `/api`, скачивание/открытие ответа; **не** `/uploads` и не файл заказа

## 📦 Результат
- раскрой в UI и PDF по запросу, без файлового следа раскроя на сервере
