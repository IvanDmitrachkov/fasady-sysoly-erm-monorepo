# ERM «Фасады Сысолы» — Стек библиотек и UI

Зафиксировано для реализации. Общая архитектура и деплой: [architecture.md](./architecture.md), [repository-and-production.md](./repository-and-production.md). Этапы из [steps.md](./steps.md) можно не соблюдать строго, если порядок в коде удобнее — но расхождения с **бизнес-требованиями** согласовывать отдельно.

---

## 1. Принципы кода

- TypeScript **strict**, явные типы на границах модулей.
- Одна ответственность у файла/модуля, предсказуемая структура `modules/<домен>/` на API и `features/` на web.
- Валидация входа API через **Zod** (схемы рядом с хендлерами или в `schemas/`).
- Без «тихих» `any`, без дублирования бизнес-правил между слоями без нужды.
- Если решение противоречит зафиксированным докам — **остановиться и уточнить**, а не подбирать костыль.

---

## 2. Backend (`apps/api`)

| Назначение | Библиотека | Примечание |
|------------|------------|------------|
| HTTP-сервер | **Fastify** | REST под префиксом `/api` |
| ORM и миграции | **Prisma** | локально SQLite, прод MySQL — см. [repository-and-production.md](./repository-and-production.md) §3.1 |
| JWT | **@fastify/jwt** | access-токен; refresh на MVP не обязателен |
| пароли | **@node-rs/argon2** или **bcrypt** (один выбрать при первом коммите пользователей) | не хранить пароль в открытом виде |
| валидация тела/квери | **Zod** + **fastify-type-provider-zod** | типобезопасные маршруты |
| CORS | **@fastify/cors** | для локального Vite при необходимости; прод — один домен |
| multipart (файлы) | **@fastify/multipart** | вложения заказов |
| статика SPA в проде | **@fastify/static** | раздача сборки под `/admin` |
| логи | **pino** (встроен в Fastify) | без лишних обёрток |
| PDF (раскрой) | **pdfkit** или **@pdf-lib/pdf-lib** | поток в ответ; без Puppeteer на MVP (тяжело для Beget) |

Переменные окружения валидировать через **Zod** при старте (`env` schema), падать с понятной ошибкой, если чего-то не хватает.

## 3. Frontend (`apps/web`)

| Назначение | Библиотека | Примечание |
|------------|------------|------------|
| UI | **React 18+** | |
| сборка | **Vite** | `base: '/admin/'` |
| язык | **TypeScript** (strict) | |
| маршрутизация | **react-router-dom** (v6+) | |
| **дизайн-система** | **Mantine v7** (`@mantine/core`, `@mantine/hooks`, `@mantine/notifications`, при необходимости `@mantine/dates`) | тема, таблицы, поля ввода, модалки, доступность; **формы не из Mantine**, см. ниже |
| данные с API | **@tanstack/react-query** (TanStack Query / React Query) | кэш, статусы загрузки, единый стиль работы с `/api` |
| формы | **react-hook-form** | контролируемая связка с полями Mantine через `Controller` / `register` + `onChange` |
| валидация форм | **Zod** + **@hookform/resolvers** (`zodResolver`) | одна схема с формой и при необходимости общая с API |
| даты и время | **dayjs** | парсинг, форматирование, сравнения; для календарных полей Mantine — **`@mantine/dates`** с **dayjs** как date library (по доке Mantine) |

Иконки: **@tabler/icons-react** (рекомендуемая пара к Mantine) или встроенные возможности Mantine.

**Mantine + React Hook Form:** Mantine даёт внешний вид и доступность полей (`TextInput`, `Select`, …), RHF — состояние формы и сабмит; дублировать `@mantine/form` не нужно.

**Почему Mantine, а не «с нуля» + Tailwind или Ant Design:** полноценная библиотека компонентов из коробки, меньше верстки с нуля, единый визуальный язык; Ant Design тяжелее и навязчивее визуально; shadcn — по сути сборка на Tailwind, больше ручной работы на MVP.

## 5. Тема и бренд (MVP)

- Использовать встроенную **тему Mantine** (`MantineProvider`, `createTheme` при необходимости).
- Кастомный бренд (логотип, фирменные цвета) — позже; на MVP достаточно аккуратной нейтральной темы и консистентных отступов из DS.

---

## 6. Явные запреты на MVP (лишний шум)

- Redux без крайней нужности (состояние сервера — React Query, локальное — `useState` / **React Hook Form**).
- Puppeteer для PDF.
- Дублирующий ORM слой поверх Prisma «для абстракции».
