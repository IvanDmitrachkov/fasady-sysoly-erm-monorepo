# ERM «Фасады Сысолы» — Архитектурные требования v1.0

---

# 1. 🧠 Общая архитектура системы

Система состоит из трёх основных частей:

- Frontend (SPA)
- Backend (API)
- Database
- File Storage (локальный)

---

# 2. 🖥 Frontend

## 2.1 Технологии
- React
- Vite
- TypeScript

## 2.2 Тип приложения
- Single Page Application (SPA)

## 2.3 Назначение
- UI для всех пользователей системы
- работа с API backend
- отображение канбана, заказов, раскроя, метрик

## 2.4 Развёртывание
- статический хостинг Beget
- деплой через GitHub Actions (build → upload)

---

# 3. ⚙️ Backend

## 3.1 Технологии
- Node.js
- TypeScript
- Fastify

## 3.2 Архитектура
- REST API
- модульная структура по доменам (orders, stages, facades и т.д.)

## 3.3 Назначение
- бизнес-логика системы
- управление заказами и этапами
- расчёт раскроя
- учёт времени
- управление файлами

## 3.4 Развёртывание
- Node.js runtime (Beget если доступно) или внешний сервер
- запуск как постоянно работающий процесс

---

# 4. 🗄 База данных

## 4.1 Тип
- MySQL (Beget)

## 4.2 Назначение
- хранение всех бизнес-данных:
    - заказы
    - фасады
    - этапы
    - пользователи
    - клиенты
    - time entries
    - история изменений

## 4.3 Доступ
- только через backend (прямой доступ из frontend запрещён)

---

# 5. 📁 File Storage

## 5.1 Тип
- локальная файловая система на сервере backend

## 5.2 Назначение
- хранение файлов (PDF, экспортов, документов)

## 5.3 Структура
- /uploads/...

## 5.4 Принцип
- файлы не являются частью бизнес-логики
- доступны через backend как static files

---

# 6. 🔗 Взаимодействие компонентов

## 6.1 Frontend → Backend
- HTTP REST API
- JSON обмен данными

## 6.2 Backend → Database
- SQL через ORM (Prisma или аналог)

## 6.3 Backend → File Storage
- запись/чтение файлов из локальной FS

---

       ↓

       ↓
