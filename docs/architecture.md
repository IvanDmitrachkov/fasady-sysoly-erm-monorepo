# 1. 🧠 Общая архитектура системы

Один **серверный проект** на Beget: один процесс Node.js обслуживает и API, и выдачу собранного фронтенда (по смыслу близко к схеме Strapi: единая точка развёртывания).

Компоненты:

- **Frontend (SPA)** — React, собирается в статику, раздаётся с того же хоста
- **Backend (REST API)** — Node.js + Fastify
- **Database** — MySQL (Beget)
- **File Storage** (локальный) — `/uploads` для вложений к заказам; резервное копирование содержимого uploads **пока не проектируется** (задел на будущее)

# 2. 🖥 Frontend

## 2.1 Технологии
- React
- Vite
- TypeScript

## 2.2 Тип приложения
- Single Page Application (SPA)

## 2.3 Назначение
- UI для всех пользователей системы
- работа с API backend
- отображение канбана, заказов, раскроя, метрик

## 2.4 Развёртывание
- один домен, один сервер Beget
- **префикс `/admin`** — админка и приложение для цеха / заказчика (SPA)
- **префикс `/api`** — HTTP REST API
- деплой через GitHub Actions (build → upload на Beget, FTP или выбранный способ хостинга)

---

# 3. ⚙️ Backend

## 3.1 Технологии
- Node.js
- TypeScript
- Fastify

## 3.2 Архитектура
- REST API под префиксом `/api`
- модульная структура по доменам (orders, stages, facades и т.д.)

## 3.3 Авторизация
- **JWT** (зафиксировано; без session-cookie как основного механизма)

## 3.4 Назначение
- бизнес-логика системы
- управление заказами и этапами
- расчёт и **генерация PDF раскроя** (поток ответа, без сохранения файла раскроя)
- учёт времени
- управление файлами (вложения заказов)

## 3.5 Развёртывание
- один долгоживущий процесс Node.js на Beget
- HTTPS и резервное копирование **MySQL** — по возможностям хостинга Beget (автоматические бэкапы БД используются как есть)

---

# 4. 🗄 База данных

## 4.1 Тип
- MySQL (Beget)

## 4.2 Назначение
- хранение всех бизнес-данных:
    - заказы
    - фасады
    - этапы
    - пользователи
    - заказчики (контрагенты)
    - time entries
    - история изменений (audit)

## 4.3 Доступ
- только через backend (прямой доступ из frontend запрещён)

## 4.4 Локальная разработка
- для разработки на машине разработчика — **SQLite** (файл, не в git), чтобы не поднимать MySQL локально; подробности и оговорка про Prisma — в [repository-and-production.md](./repository-and-production.md) §3.1.

---

# 5. 📁 File Storage

## 5.1 Тип
- локальная файловая система на сервере backend

## 5.2 Назначение
- хранение вложений к заказам (документы и т.п.), **не** PDF раскроя

## 5.3 Структура
- `/uploads/...`

## 5.4 Принцип
- файлы не являются частью бизнес-логики раскроя
- доступны через backend
- отдельная политика бэкапов для каталога uploads **на будущее**

---

# 6. 🔗 Взаимодействие компонентов

## 6.1 Frontend → Backend
- HTTP REST API на том же домене: `/api/...`
- JSON обмен данными; для PDF раскроя — **бинарный ответ** (например `application/pdf`)

## 6.2 Backend → Database
- SQL через **Prisma** (см. [technology-stack-and-ui.md](./technology-stack-and-ui.md))

## 6.3 Backend → File Storage
- запись/чтение файлов из локальной FS

# 7. 🌐 Сетевая архитектура

```txt
[ Браузер ]
    |  один домен (Beget)
    ├── GET /admin/*  → SPA (React)
    └── /api/*        → Node.js (Fastify) + JWT
              ↓
         [ MySQL ]
              ↓
         [ /uploads — вложения, не раскрой ]
```
