# ERM «Фасады Сысолы» — Business Requirements v1.0

---

# 1. 🎯 Назначение системы

Система предназначена для управления производством фасадов:

- ведение заказов
- контроль этапов производства
- расчёт стоимости фасадов
- генерация раскроя
- учёт трудозатрат
- анализ узких мест производства (по этапам)

---

# 2. 👥 Роли пользователей

## 2.1 Администратор
- полный доступ к системе
- управление пользователями
- управление заказчиками
- управление заказами и этапами

## 2.2 Работник (цех)
- просмотр и обработка заказов
- изменение статусов внутри этапа (UI-only)
- перенос заказов между этапами (канбан)
- внесение трудозатрат (time tracking)
- не привязан к конкретному этапу

## 2.3 Заказчик
- просмотр своих заказов (read-only)
- без доступа к управлению производством и справочниками

---

# 3. 🧱 Сущность: Заказ

## 3.1 Поля заказа
- номер заказа (6 цифр, авто)
- дата создания
- дата дедлайна
- заказчик
- текущий этап
- комментарий
- итоговая стоимость

## 3.2 Принцип системы
> Заказ = единственная процессная сущность

---

# 4. 🏭 Производственный процесс (этапы)

## 4.1 Этапы (канбан-точки)

- Новый (входная стойка)
- Раскрой
- Подготовка
- Покраска / Плёнка (камера)
- Полировка / Шлифовка
- Упаковка
- Отгрузка (выходная стойка)

## 4.2 Свойства этапов
- динамические (редактируются через UI)
- линейный порядок
- этап = физическая точка производства

## 4.3 Канбан-переход
- заказ всегда в одном этапе
- переход только вперёд
- ручной перенос пользователем

---

# 5. 🏷 Внутренний статус этапа (UI-only)

## 5.1 Статусы
- В работе
- Заблокирован
- Готов

## 5.2 Правила
- не влияет на бизнес-логику
- не влияет на переходы
- не участвует в аналитике
- может не использоваться

## 5.3 Назначение
- визуализация состояния внутри этапа

---

# 6. 🧱 Сущность: Фасады

## 6.1 Поля
- фрезеровка
- покрытие
- цвет
- размеры (мм)
- толщина (мм)
- интегрированная ручка
- радиус завала торца
- дополнительные опции (text)

## 6.2 Цена
- базовая цена (расчётная)
- переопределение:
    - процент (скидка / наценка)
    - фиксированная сумма
- итоговая цена

## 6.3 Роль
- данные заказа
- не участвует в процессе
- не имеет статусов

---

# 7. 🪵 Модуль «Раскрой»

## 7.1 Принцип
> Stateless операция над заказом

- не сохраняется
- пересчитывается с нуля

## 7.2 Вход
- заказ
- фасады

## 7.3 Логика
1. группировка:
    - материал (MVP: MDF)
    - толщина
2. раскрой по группам
3. каждая группа = отдельная страница

## 7.4 Выход
- набор страниц раскроя
- схемы размещения

## 7.5 Ограничения MVP
- нет остатков
- нет версий
- нет сохранения результата раскроя и PDF на сервере (только отображение и выдача PDF клиенту)
- нет редактирования

## 7.6 UI
- кнопка “Раскрой”
- новая вкладка
- визуализация
- PDF: генерация для скачивания у клиента, без сохранения в файловом хранилище заказа

---

# 8. 📏 Материалы

## MVP
- MDF

## Будущее
- материал как сущность

---

# 9. ⏱ Time Tracking

## 9.1 Принцип
- ручной ввод времени
- без автоматизации

## 9.2 Time Entry
- заказ
- пользователь
- этап
- время
- комментарий
- дата

## 9.3 Возможности
- множественные записи
- задним числом
- привязка к этапу

---

# 10. 📊 Метрики

## Принцип
> Метрики считаются только по этапам

## 10.1 Заказные метрики
- lead time
- просрочки
- общее время

## 10.2 Этапные метрики
- очередь
- время обработки
- загрузка
- узкие места

## 10.3 Ограничения
- нет метрик по статусам
- нет внутриэтапной аналитики

---

# 11. 📜 Audit Log

Фиксируется:
- смена этапа
- изменения заказа
- изменения фасадов
- изменения цены

Поля:
- пользователь
- время
- тип изменения
- diff (старое/новое)

---

# 12. 💰 Ценообразование

- динамическое
- может изменяться в любой момент
- не фиксируется окончательно

---

# 13. 🧾 Заказчики

- могут быть без аккаунта
- могут иметь несколько записей
- привязка к заказам

---

# 14. 🖥 UI модули

- список заказов
- карточка заказа
- канбан этапов
- модуль раскроя
- пользователи
- заказчики (справочник для админа)
- кабинет заказчика: свои заказы (просмотр)

---

# 15. ⚠️ Ограничения MVP

- нет авто-трекинга времени
- нет сохранения раскроя и PDF раскроя на сервере
- нет остатков материалов
- нет сложной оптимизации
- нет AI/прогнозирования
- нет версионирования заказов
- нет обязательных статусов

---

# 16. 🧠 Архитектура

## Слои

### 1. Order (процесс)
- движение по этапам

### 2. Facades (данные)
- описание изделия

### 3. Cutting (операция)
- stateless расчет

### 4. Time Entries (факты)
- ручные записи

### 5. Metrics (аналитика)
- только по этапам

---

## Принципы системы

- заказ = поток
- этап = физическая точка
- фасад = данные
- раскрой = функция
- статус = UI слой

---

# 🏁 Итог

Система представляет собой production-oriented order management system для цеха фасадов с физическим потоком заказов через этапы, stateless расчётом раскроя и событийным учётом времени.
